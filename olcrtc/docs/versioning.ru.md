# Версии

**RU** / [EN](versioning.md)

Версии движка - это git-теги вида `vMAJOR.MINOR.PATCH` на коммитах ветки
`proofkit`. У каждого тега есть
[релиз на GitHub](https://github.com/ghostlane-project/olcrtc/releases): что
изменилось с предыдущего и где этот движок стоит.

## Правила

- **MINOR** растёт при новом операторе, новом поведении или изменении того, что
  видит другая сторона: рукопожатия, кадров, YAML сервера. **PATCH** растёт при
  изменении, которое ничего из этого не трогает: исправление внутри одной
  стороны, гейт, тесты, документация. MAJOR остаётся 0, пока Go API может
  меняться.
- **Тег не передвигается и не удаляется.** База контрольных сумм Go хранит
  коммит каждой версии, которую отдал прокси, поэтому передвинутый тег сломал бы
  каждую следующую сборку, которая его уже знала. Ошибка исправляется следующей
  версией.
- **Каждый движок, который куда-то уходит, сначала получает тег**: и пин
  клиента, и серверная сборка. В релизе написано, что его поставляет.
- **Потребители называют версию.** Модуль сохраняет путь upstream, поэтому в Go
  это `require github.com/openlibrecommunity/olcrtc vX.Y.Z` и
  `replace github.com/openlibrecommunity/olcrtc => github.com/ghostlane-project/olcrtc vX.Y.Z`.
- **Бинарник называет свою версию.** `olcrtc -version` печатает её, а первая
  строка каждого запуска пишет её в лог. Сборка из чистой копии тега называет
  тег (`v0.12.0`). Любая другая сборка называет псевдоверсию после последнего
  тега: в ней есть коммит, а `+dirty` в конце значит, что в дереве были
  изменения.

## Как выпустить версию

1. Изменение влито в `proofkit`, и CI вместе с гейтом зелёный на этом коммите.
2. Поставить тег и отправить его:

   ```sh
   git tag -a vX.Y.Z <commit> -m "olcRTC vX.Y.Z"
   git push origin vX.Y.Z
   ```

3. Выпустить релиз для тега: что изменилось с предыдущего тега, по его слияниям,
   и где он стоит. Добавить строку в таблицу ниже.
