# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят только для **последнего релиза**. Прежде чем сообщать о проблеме,
обнови приложение со [страницы релизов](https://github.com/yanisplugg/olcvpn-client/releases/latest).

| Сборка | Поддержка |
|--------|-----------|
| последний релиз — Android, Windows (x64 / ARM64), Linux (`.deb`, x64 / ARM64) | ✅ |
| iOS | 🧪 бета: сообщения принимаем, но сроков исправления не обещаем |
| старые релизы, сборки из веток `Beta` / `pc-client-beta` | ❌ |

Официальные файлы — только те, что приложены к релизам этого репозитория. APK подписаны одним ключом,
отпечаток сертификата (SHA-256):

```
EA:6B:8C:6B:13:53:D9:C1:10:86:CD:7E:75:25:92:10:B2:6A:1B:11:A6:93:02:92:27:0E:EC:CC:B1:9F:4E:D0
```

Проверить: `apksigner verify --print-certs YPtun-*.apk` или `keytool -printcert -jarfile YPtun-*.apk`.
APK с другим отпечатком — не наш, даже если называется так же.

## Как сообщить об уязвимости

**Пожалуйста, не открывай публичный issue по уязвимостям.**

Сообщи приватно через
[**Security Advisories**](https://github.com/yanisplugg/olcvpn-client/security/advisories/new)
на GitHub — вкладка «Security» → «Report a vulnerability» (нужен вход в аккаунт GitHub). Укажи:

- описание проблемы и её влияние,
- шаги воспроизведения или proof of concept,
- версию приложения, платформу (Android / Windows / Linux / iOS) и версию ОС,
- движок и тип подключения, если проблема связана с ними,
- журнал подключения, если он помогает, — **сначала убери из него** адреса серверов, ключи, токены,
  ссылки подписок.

Постараемся ответить за несколько дней и будем держать в курсе по исправлению. Дай разумное время на
выпуск патча до публичного раскрытия.

## Что особенно важно

Это инструмент обхода блокировок: от него зависит, что пользователь не окажется на виду. Особенно
ценны сообщения про:

- **утечки мимо туннеля** — трафик, DNS или IP (IPv4 **или** IPv6) уходят напрямую; в том числе
  при обрыве связи, переподключении, смене сети или падении приложения, на любой платформе и в любом
  режиме (TUN или прокси);
- **отпечатки**, по которым наблюдатель может надёжно отличить трафик YPtun — у любого движка
  (Xray / sing-box, AmneziaWG, VK-TURN, olcRTC, MasterDNS, OpenFlux, Trust Tunnel);
- **недоверенный ввод** — подписки, ссылки (`vless://`, `yptun://inbound` и др.), QR-коды, файлы,
  полные конфиги Xray / sing-box, deep links: падения, порча памяти, выполнение кода, подмена настроек
  других локаций;
- **локальные порты** — SOCKS/HTTP-прокси приложения, мост для расширения Chrome и порт импорта ссылок
  на `127.0.0.1` (ПК): если ими может воспользоваться другое приложение или веб-страница сверх
  задуманного (мост пускает только запросы расширения с защитным заголовком, импорт принимает только
  ссылку);
- **повышение привилегий на ПК** — части, работающие с правами root (Linux, через pkexec) или
  администратора (Windows, TUN-адаптер wintun), и изменения системных настроек (маршруты, DNS,
  системный прокси), которые не возвращаются обратно;
- **секреты пользователя** — ключи и конфиги, пароли и ключи SSH для автоустановки серверов на VPS,
  токены сервисов (VK, MAX), ссылки подписок: хранение на устройстве, попадание в журналы или к третьим
  лицам;
- **автоустановка серверов** — скрипты, которые приложение выполняет на VPS по SSH;
- **обновления** — обновление из приложения и дельта-патчи: возможность подсунуть чужую сборку.

## Вне этой политики

- Уязвимости самих вендоренных ядер (Xray, sing-box, AmneziaWG, olcRTC, OpenFlux, qWDTT и др.) —
  сообщай их авторам. Нам — если YPtun использует ядро небезопасным образом или отстал от исправленной
  версии.
- Серверная сторона, которой нет в этом репозитории: панели, чужие серверы и подписки.
- Блокировка конкретного протокола или сервиса цензором — это не уязвимость, а обычный
  [issue](https://github.com/yanisplugg/olcvpn-client/issues).

Спасибо, что помогаешь защитить пользователей. 🛡️
