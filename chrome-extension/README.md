# YPtun VPN — Chrome extension

Вставил ссылку → включил → браузер ходит через твою локацию. **Ничего на сервере настраивать не
надо**: работают `tcp`, `xhttp`, `ws`, `grpc`, TLS, **REALITY**, vision — всё, что умеет само
приложение YPtun.

Расширение — по-прежнему чистый JS, без нативных хостов и бинарников. Движком служит **уже
установленный YPtun**: расширение отдаёт ему ссылку и указывает Chrome на локальный порт, который
приложение поднимает.

## Почему именно так

У MV3-расширения нет ни сырых сокетов, ни возможности слушать порт. Отсюда две жёсткие вещи, которые
обойти нельзя:

* **VLESS в самом браузере не реализуем.** Единственный способ увести трафик Chrome — `chrome.proxy`,
  а он умеет только указать на прокси, до которого браузер дойдёт сам (HTTP/HTTPS/SOCKS).
* **REALITY в браузере невозможен в принципе.** Ему нужен собственный ClientHello, а TLS-стек Chrome
  не программируется из JS. Ни расширением, ни WASM.

Поэтому прокси должен быть **на этой машине**, и за ним должно стоять настоящее ядро. Оно уже есть —
это YPtun. Расширение общается с ним по `127.0.0.1:47639` (только петля, только с
`chrome-extension://`-origin) и направляет браузер на HTTP-прокси `127.0.0.1:47640`, который
приложение поднимает перед локальным SOCKS ядра.

Прошлая схема держала прокси **на сервере** (отдельный xray-инбаунд `http` под TLS). Она требовала
второго инбаунда, настоящего сертификата Let's Encrypt и **не умела REALITY** — от неё отказались.

```
vless://… ──вставили──> [расширение] ──127.0.0.1:47639──> YPtun (xray / sing-box / AWG)
                              │                                    │
                              └── chrome.proxy ──> 127.0.0.1:47640 ─┘
```

## Как пользоваться

1. Запустить YPtun (десктопное приложение).
2. В расширении: `+` → вставить ссылку → «Сохранить» → выбрать локацию → кнопка питания.

Подойдёт любая ссылка, которую понимает приложение: `vless://`, `vmess://`, `trojan://`, `ss://`,
`hy2://`, `yptun://inbound…`. Локация добавляется в само приложение — она же видна в его списке.
Повторное подключение по той же ссылке дубля не создаёт.

После включения расширение **проверяет прокси реальным запросом** и, если трафик не идёт, сразу
снимает настройку — браузер никогда не остаётся с нерабочим прокси. Причина пишется в попапе:
приложение не запущено, ссылка не распознана, ядро не поднялось (тогда смотреть журнал в YPtun),
порт занят, или туннель поднят, но трафика нет.

**Исключения** (Настройки) — хосты мимо туннеля, по одному в строке; `localhost`, `127.0.0.1`,
`[::1]` и `<local>` исключены всегда.
**Язык** — Авто / Русский / English.

## Установка расширения

Архив релиза (`python chrome-extension/pack.py` → `dist/yptun-chrome-<версия>.zip`) распаковать в
любую постоянную папку, затем: `chrome://extensions` → «Режим разработчика» → «Загрузить
распакованное» → указать эту папку. Папку не удалять и не переименовывать — расширение живёт в ней.

**Почему не установщик в один клик:** с Chrome 73 пакет ставится, только если подписан Chrome Web
Store (иначе `CRX_REQUIRED_PROOF_MISSING`), локальный `.crx` через реестр Chrome тоже больше не
берёт, а флаг `--load-extension` вырезан в Chrome 137. Один клик = либо публикация в Web Store
(разово $5), либо корпоративная политика `ExtensionInstallForcelist` со своим `update.xml`.

ID расширения зафиксирован полем `key` в манифесте: `liobljilajeajepjcoppcjghalnlgcjf`.

## Известные ограничения

* нужен запущенный YPtun — иначе трафик нести нечем (см. выше, это не обходится);
* через туннель идёт только трафик браузера (для всей системы — режим прокси/TUN в самом приложении);
* WebRTC может ходить мимо прокси и светить реальный IP — при необходимости добавляется
  `chrome.privacy.network.webRTCIPHandlingPolicy`;
* QUIC/HTTP3 через HTTP-прокси не идёт — Chrome сам откатится на TCP.
